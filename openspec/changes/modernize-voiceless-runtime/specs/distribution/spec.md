# 发行与升级规格增量

## Purpose

让不同安装渠道都能获得可验证的 Voiceless 产物和明确的运行要求。用户可安全升级、确认当前运行版本并按安装渠道恢复，继续使用已有设置、模型与历史。

## ADDED Requirements

### Requirement: 平台交付与运行依赖可验证

Linux 成套交付 MUST 包含可独立运行的 daemon、CLI、内嵌 Web、独立桌面窗口与托盘集成。核心包 MUST 保留 Linux x86-64 和 ARM64 的 glibc 2.35 兼容范围及已发布的推理能力。macOS 和 Windows MUST 分别提供可安装的桌面和命令行产物，公开列出实测功能与依赖。

#### Scenario: Linux 发布包离线运行

- **WHEN** 用户在 Linux x86-64 或 ARM64 的支持环境安装 Nix、Bun 或独立发布包，并已备好适配模型
- **THEN** 可运行 CLI、离线本地听写和 `voiceless web`，核心包无需 Node、Bun 或 WebView 运行时即可完成这些操作

#### Scenario: Linux 桌面或跨平台安装

- **WHEN** 用户在支持的 Linux 桌面、macOS Apple Silicon 或 Windows x64 安装并首次启动相应桌面产物
- **THEN** 能用桌面入口完成麦克风、快捷键、首次试说、上屏和再打开窗口的验收，缺失的可选桌面能力有明确诊断

### Requirement: 安装渠道归属和回滚

更新 MUST 由当前安装渠道负责，展示目标版本与实际运行的运行时版本。活动听写完成后方可切换进程。独立安装 MUST 提供经校验的上一版回滚，包管理器和系统管理的安装使用各自的更新路径。

#### Scenario: 从 Bun 或 Nix 现有安装升级

- **WHEN** 用户从 `0.1.3` Bun 或 Nix 安装升级并重开控制台
- **THEN** 现有命令、服务入口与配置继续可用，可区分已安装与正在运行的版本，更新没有写入其他安装渠道

#### Scenario: 更新验证失败或用户回滚

- **WHEN** 候选包完整性校验失败、进程切换失败或用户请求回到上一可用版
- **THEN** 当前使用的版本可继续工作，或按该渠道的恢复路径重新启用上一版，并可用升级前的数据备份恢复兼容状态

### Requirement: 发布验证与数据迁移证据

发布 MUST 验证实际安装产物、升级旧配置和历史、离线启动与可用的设备路径。所承诺的平台、桌面能力和回退路径 MUST 有对应验证结果，缺失的实机证据须标记未验证。

#### Scenario: 对现有 Linux 部署执行升级验收

- **WHEN** 使用候选包升级与 Apollo 等目标机相同的 Linux 用户服务和 `0.1.3` 数据
- **THEN** 配置、模型、历史和录音可继续读取，快捷键及 Web 入口工作，实际 Vulkan、无驱动 CPU 和 ARM64 CPU 路径分别记录验证结果
