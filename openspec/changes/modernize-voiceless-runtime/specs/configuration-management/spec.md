# 配置管理规格增量

## Purpose

允许用户从控制台、桌面、命令行或 TOML 配置管理设置。每次修改都有明确的保存和生效结果，编辑冲突、启动失败和升级时可以恢复可用配置。

## ADDED Requirements

### Requirement: 并行编辑与变更冲突

编辑入口 MUST 标明配置版本，并且只提交编辑过的字段。来自同一旧版本的不同字段变更 MUST 可以合并。同字段的相互冲突变更 MUST 返回可比较的当前值，保留未保存草稿。密钥字段只提供存在状态和编辑选择。

#### Scenario: 两个客户端修改同一节的不同字段

- **WHEN** 一个页面将设备从 CPU 改为 Vulkan，另一个已打开的页面只修改线程数
- **THEN** 两项都能保存，线程数变更不会覆盖 Vulkan 设置

#### Scenario: 同字段被其他客户端或文件编辑器修改

- **WHEN** 草稿改动的字段在保存前已被不同值修改
- **THEN** 界面提示冲突并保留草稿，用户可采用当前值或重新确认覆盖，当前配置保持完整

### Requirement: 严格配置与私密数据保护

设置保存 MUST 使用与 CLI 一致的规则校验，并保留 TOML 注释与未编辑的配置。有效配置只在完整写入后替换，含凭据的配置与备份权限 MUST 不宽于 `0600` 或等效的用户访问限制。

#### Scenario: 保存不合法或写入被中断

- **WHEN** 用户提交未知字段、无效值，或保存未能完成
- **THEN** 返回相关字段或写入错误，已生效配置和上一个有效文件可继续使用

#### Scenario: 导出设置和移除凭据

- **WHEN** 用户导出设置模板或显式清除一个已保存密钥
- **THEN** 导出内容和客户端响应不含密钥值，清除只影响指定凭据，未修改的凭据继续可用

### Requirement: 配置保存与运行时生效分离

对需要重建识别引擎、快捷键或音频设备的修改，界面 MUST 分别显示已保存和实际生效状态。运行中会话使用开始时的配置。请求应用时若资源验证失败，MUST 保留上一套可用运行配置，并提供修正、重试或恢复入口。

#### Scenario: 录音中申请应用新设置

- **WHEN** 录音期间保存并请求应用新的识别模型或快捷键
- **THEN** 当前录音按原设置完成，界面指出等待空闲，并在空闲后报告成功生效或失败

#### Scenario: 新模型或快捷键加载失败

- **WHEN** 空闲后尝试应用缺失的模型、不能初始化的设备或不能注册的快捷键
- **THEN** 显示具体失败原因，上一套可用设置仍能开始听写，用户可以恢复已保存的设置或修正后重试
