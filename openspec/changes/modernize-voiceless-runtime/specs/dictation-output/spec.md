# 听写输出规格增量

## Purpose

让同一听写能力适用于编程、聊天、写作和翻译。用户可以选择当前模式、调整词库与处理顺序，并检查从原始识别到最终交付的变化和耗时。

## ADDED Requirements

### Requirement: 按目标选择可预览的输出流程

用户 MUST 能编辑现有和新增的输出模式，启停并排序支持的步骤，使用同一段样本文本预览每一步及其差异。匹配的应用规则 MUST 有可见的优先级，手动选择优先，缺少可靠目标信息时使用已选默认模式。

#### Scenario: 从不同应用听写同一句话

- **WHEN** 同一段语音分别在终端和聊天应用中使用各自的已启用规则识别
- **THEN** 依次执行对应步骤，显示命中的模式和经过的步骤，终端模式可以保留数字、路径、代码和原有换行

#### Scenario: 原文直出或处理步骤失败

- **WHEN** 用户选择原文直出，或启用的润色、翻译等处理步骤超时或失败
- **THEN** 原文直出交付权威识别文字，失败路径提供可读原因和可选择使用的安全结果，正常 `quick` 模式不调用远程文本处理

### Requirement: 术语管理与纠错回流

词库 MUST 支持全局及模式或项目范围的热词、替换和正则规则，提供导入、去重和导出。界面 MUST 说明词条作用于识别、文本清理或两者，并允许将用户确认的纠错差异加入所选范围。

#### Scenario: 导入术语并从历史纠错补充词库

- **WHEN** 用户导入含重复条目的中文专名与英文 API 名，再把一条纠错保存到项目词库
- **THEN** 预览显示合并及冲突结果，只有确认的条目生效，其他模式不承受项目专属替换

#### Scenario: 针对模型查看词条支持

- **WHEN** 当前模型不能使用词条做识别偏置，或需要设置特定语言
- **THEN** 页面明确显示支持能力和实际作用阶段，用户仍可预览清理后的混合语言结果

### Requirement: 自动化扩展由用户选择

自动化入口 MUST 通过同一运行时读取状态、试跑输出或请求会话。OpenCode、外部处理服务、自定义脚本和网站上下文均须由用户启用，展示输入范围与权限。脚本执行失败不得重复交付或丢失已识别文字。

#### Scenario: 显式配置远程处理或脚本

- **WHEN** 用户为一个模式启用远程处理或导入第三方脚本
- **THEN** 可先查看数据用途、权限和预览结果，获得对应授权后该模式才会执行它，默认模式保持原行为

#### Scenario: 使用 CLI 或 OpenCode 预览结果

- **WHEN** 有权限的本机客户端请求试跑模式，或脚本超过配置的时限
- **THEN** 试跑返回结构化结果且不上屏，超时可诊断，原识别结果可恢复，未经授权的调用被拒绝
