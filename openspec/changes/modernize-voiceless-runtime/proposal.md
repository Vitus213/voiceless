# Voiceless 全链路重构提案

## Why

Voiceless 已有本地和云端听写、常驻服务与 Web 控制台，但用户仍需从日志确认实际 GPU、回退和上屏结果，多个设置页面还可能覆盖彼此的修改。Hex 的桌面宿主、能力发现和首次试说提供了可借鉴的设计，Voiceless 可以据此把安装、日常听写、纠错和故障恢复串成完整流程。 [Hex 3.4.0](https://github.com/anomalyco/hex/releases/tag/v3.4.0)

## What Changes

- 统一麦克风、快捷键、识别、文本处理和上屏的会话生命周期。CLI、Web、桌面窗口和浮层展示相同的实际设备、后端、回退和交付状态。
- 合入现有控制台重设计，提供首次试说、模型与设备选择、设置搜索、可信的配置保存和应用反馈。Linux 首次成套交付包含独立桌面窗口、支持时的托盘，以及会话关闭窗口后的持续运行。
- 增加按应用选择的输出流程、词库与纠错回流、原文直出和重贴。允许用户预览各步骤，选择本地或远程处理服务，并显式启用扩展。
- 扩展历史搜索、版本恢复、文本与音频保留及导出。支持可恢复的音视频转写队列，以及按平台能力开启的会议记录和屏幕标注工作流。
- 按能力验证 Linux、macOS 和 Windows 的麦克风、快捷键、浮层和上屏。现有 CLI 和内嵌 Web 继续随无桌面依赖的发行包提供，桌面和系统集成按平台交付。
- 保留现行 `voiceless` 命令、Nix/Bun/独立安装的更新归属、已安装模型、设置和历史。ASR 规格同步到 Rust 已生效的配置，记录旧 Python 后端的迁移方式。

## Capabilities

### New Capabilities

- `dictation-runtime` — 统一听写生命周期、回连和延迟验收。
- `configuration-management` — 跨客户端并行编辑、保存、生效和恢复。
- `web-console` — 共享控制台体验、首次试说、设置和本地访问。
- `desktop-integration` — 独立窗口、托盘、平台能力、快捷键、提示浮层和上屏。
- `dictation-output` — 有序的输出步骤、应用规则、词库和自动化。
- `recognition-library` — 历史搜索、回放、版本、保留和导出。
- `transcription-jobs` — 音视频导入、后台转写、任务恢复和字幕导出。
- `capture-workflows` — 独立的会议采集和屏幕反馈工作流。
- `distribution` — 各平台交付、更新归属、兼容性与回滚。

### Modified Capabilities

- `asr` — 更新批量和实时后端的现行行为，移除已停用的最终校准配置，增加明确的回退、实际推理设备、隐私与模型管理要求。

## Impact

- 影响 Rust 会话协调、识别引擎、配置与历史持久化，及 Web、CLI、D-Bus、浮层、桌面窗口和上屏入口。现有入口纳入兼容性验收。
- Linux 首次成套交付覆盖新版控制台和完整桌面听写。输出、历史、长音频、macOS/Windows、会议和标注分别验收，均属于本变更的交付计划。
- 发布验证覆盖已有安装升级和降级、数据兼容、包依赖、离线启动、实时听写及平台实机路径。
